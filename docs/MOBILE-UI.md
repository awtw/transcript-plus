# Transcript Plus 行動版：UI／UX 設計與上架規範

日期：2026-10-07｜狀態：設計提案，尚未實作畫面。架構見 [MOBILE.md](MOBILE.md)。

商店政策與系統版本要求會變動；**本文件的上架項目僅作為設計與檢查依據，送審前須對照 Apple App Store Review Guidelines、Human Interface Guidelines 與 Google Play 政策的最新版本逐項確認。**

## 1. 為什麼要重新設計

桌面版是「左側清單＋中間播放＋右側多分頁」的寬螢幕工作台（`App.tsx` 約 2,100 行）。手機需要：單手操作、單欄、一次只做一件事、拇指可及的主要動作，以及符合各平台的導覽慣例。因此不縮小桌面版面，而以「手機上的任務」重新組織。

## 2. 設計原則

1. **一個畫面一個任務**：匯入／錄音、等待、校對、整理、匯出各自成頁。
2. **主要動作在拇指區**：底部分頁列、底部浮動錄音鈕、底部操作表單（sheet）。
3. **進度永遠可見且誠實**：顯示階段與已處理時間；不能估算時只顯示階段，不顯示假百分比。
4. **不丟資料**：任何編輯即時保存；被系統終止後回來要停在原處。
5. **隱私即賣點**：畫面明確標示「全程在本機處理」，且事實必須成立（不含任何上傳）。
6. **遵循平台語彙**：iOS 用 SwiftUI 的原生元件與 SF Symbols；Android 用 Material 3 元件與動態色彩。兩者資訊架構相同，視覺各依平台。

## 3. 資訊架構

```text
底部分頁（3 個，iOS TabView／Android NavigationBar）
├─ 專案        專案列表（搜尋、排序、狀態標籤）
│   └─ 專案詳情
│       ├─ 逐字稿   （預設）播放器＋段落列表，點段落跳播、編輯
│       ├─ 講者     分群、改名、合併、聲紋
│       ├─ 摘要     摘要／決議／待辦，引用可點回原文
│       └─ 字幕     字幕列表、拆合、時間微調
├─ 錄音        新增錄音（大型錄音鈕）、匯入檔案
└─ 設定        模型管理、處理選項、語言、隱私、關於
```

專案詳情的四個區塊在手機上用頂部分段控制（iOS Picker segmented／Android 分頁列），不再另設底部分頁，避免雙層導覽。

## 4. 主要畫面

### 4.1 專案列表
- 每列：標題、時長、日期、狀態標籤（排隊／處理中＋階段／完成／失敗／中斷）。
- 處理中的列顯示階段文字與細進度條；失敗與中斷顯示「重試」。
- 左滑（iOS）或長按（Android）：重新命名、分享、刪除（刪除須確認，且說明會刪除原檔副本）。
- 空狀態：說明「錄音或匯入音訊，全程在手機上處理」，附兩個按鈕。

### 4.2 新增（錄音／匯入）
- 錄音：大圓鈕、音量條、計時；暫停／繼續；來電或被中斷時自動保存已錄內容並提示。
- 錄音前第一次顯示一次性提示：「錄製他人聲音前，請先取得對方同意」。
- 匯入：系統文件選擇器、iOS 相簿影片、其他 App 的「分享到 Transcript Plus」。
- 匯入後顯示轉錄設定（單一 sheet）：語言、品質（品質／平衡／快速）、是否分辨講者、是否產生摘要。預設值依裝置能力選擇；設定頁可改預設。

### 4.3 處理中
- 顯示階段（準備音訊→載入模型→轉錄→講者→儲存）、已處理／總時長、耗時。
- 即時預覽已轉出的文字（桌面版已有此能力）。
- 「取消」永遠可用；說明離開此頁處理仍會繼續（前景）／可能被系統暫停（背景），並提供「保持螢幕開啟」開關。
- 溫度過高或低電量時顯示暫停原因與繼續按鈕，不靜默失敗。

### 4.4 逐字稿校對（核心畫面）
- 頂部：精簡播放器（播放／倍速／後退 10 秒／前進 10 秒、拖曳列）；影片專案顯示可收合的小視窗。
- 下方：虛擬化段落列表；目前播放段落高亮並自動捲動，使用者手動捲動時暫停自動捲動並顯示「回到目前播放」。
- 點段落：跳播；再點或點編輯：進入底部編輯 sheet（文字輸入、講者、此段重新播放）。
- 自動儲存：不使用「儲存」按鈕；以小字顯示「已儲存」或「儲存失敗，將重試」；失敗時保留草稿。
- 復原／重做：工具列按鈕，行為同桌面（當次編輯工作階段）。
- 找字：頂部搜尋，結果在列表高亮。
- 文字被改且詞級時間失效時，該段顯示淡色標記「時間為段落級」，不顯示假精準的逐詞高亮。

### 4.5 講者
- 分群卡片：顏色＋名稱＋發言總時長＋試聽片段。
- 操作：改名、合併（選擇目標）、把個別段落改歸其他分群、註冊聲紋。
- 未確認身分的自動命名顯示「待確認」，不得呈現成確定結果。顯示相似度時標明不是答對機率。

### 4.6 摘要
- 區塊：摘要重點、決議、待辦（含負責人與期限）。
- 每一項附「來源」按鈕，點擊跳到逐字稿原文；逐字稿若在摘要後被修改，顯示「已過期」並提供重新產生。
- 摘要為可選功能，需先下載摘要模型；未下載時顯示清楚的前往下載入口，不是空白頁。

### 4.7 匯出與分享
- 點「分享」開啟系統分享表單（iOS ShareSheet／Android Sharesheet）。
- 格式選擇 sheet：TXT、SRT、VTT、JSON。字幕過期或時間重疊時阻擋 SRT／VTT 並說明原因與修正入口。
- 檔案先寫入暫存再交給系統，不要求額外儲存權限。

### 4.8 設定與模型管理
- 模型列表：名稱、用途、大小、狀態（未下載／下載中／已驗證／錯誤）、下載／刪除。
- 下載：預設僅 Wi-Fi，可續傳；完成後驗證 hash 才啟用；顯示儲存空間不足的明確訊息。
- 隱私頁：說明資料位置、確認無分析追蹤、提供「刪除所有資料」。
- 授權頁：列出模型與第三方函式庫授權。

## 5. 互動與視覺規範

| 面向 | 規範 |
|---|---|
| 觸控尺寸 | iOS 最小 44×44 pt；Android 最小 48×48 dp。 |
| 安全區域 | 內容避開動態島／瀏海、Home 指示條、Android 手勢導覽列；Android 15 目標版本預設全螢幕（edge-to-edge），需處理 insets。 |
| 色彩 | 淺色／深色模式皆完整支援，跟隨系統；Android 支援動態色彩（Material You）。對比符合 WCAG AA（文字 4.5:1）。不只以顏色傳達狀態（搭配圖示或文字）。 |
| 字型 | iOS 使用 Dynamic Type；Android 使用 sp 並測試最大字級（200%）；中文字型用系統字型。逐字稿版面在最大字級下不得截斷。 |
| 動畫 | 尊重「減少動態效果」設定；播放高亮不依賴動畫。 |
| 觸覺 | 錄音開始／停止、刪除確認使用輕觸覺回饋，可由系統設定關閉。 |
| 螢幕方向 | 手機預設直向；影片播放可橫向全螢幕；平板（iPad／Android 平板）使用雙欄（列表＋詳情），不是拉伸手機版。 |
| 本地化 | 首版繁體中文、英文；字串全部走資源檔（iOS String Catalog、Android strings.xml），不寫死在畫面程式。 |

## 6. 無障礙

- 所有按鈕、段落、進度皆有明確的 VoiceOver／TalkBack 標籤；播放狀態與進度以文字朗讀（例如「轉錄中，已處理 12 分 30 秒，共 45 分鐘」）。
- 逐字稿段落的朗讀順序：時間、講者、文字；編輯按鈕有獨立標籤。
- 進度更新使用適當的 live region／accessibility announcement，避免每秒朗讀。
- 支援鍵盤與外接開關控制的焦點順序；支援「語音控制」。
- 錄音鈕需有非手勢的替代操作。

## 7. 隱私與合規設計

| 項目 | 設計 |
|---|---|
| 資料處理位置 | 轉錄、講者、摘要全在本機；不使用第三方分析或廣告 SDK（若日後加入須更新所有申報）。 |
| 網路使用 | 僅限「模型下載」與使用者主動開啟的外部連結；設定頁清楚說明。 |
| 錄音權限 | 僅在使用者按錄音時才請求；說明文字具體說明用途。 |
| 帳號 | 不需要帳號；因此無需帳號刪除流程，也不需要第三方登入選項。若日後新增帳號，須依商店規定提供 App 內刪除帳號。 |
| 聲紋 | 屬生物辨識性質的資料，須由使用者明確啟用，說明用途、儲存於本機、可隨時刪除；並於商店隱私申報中確認如何歸類。 |
| 資料保護 | iOS 使用檔案保護等級（Data Protection）；Android 使用 App 私有目錄，不寫入公共儲存空間。 |
| 刪除 | 刪除專案移除資料庫列與原檔副本；設定內提供清除全部資料。 |

## 8. 上架檢查表

### Apple App Store

- [ ] **Info.plist 用途說明**：`NSMicrophoneUsageDescription`（錄音）、若讀取相簿則 `NSPhotoLibraryUsageDescription`；文字具體、非泛用語。
- [ ] **Privacy Manifest**（`PrivacyInfo.xcprivacy`）：宣告使用的「必要原因 API」（例如檔案時間戳記、磁碟空間、UserDefaults 等，視實際使用而定）與第三方 SDK 的清單；連結的靜態函式庫（sherpa-onnx、llama.cpp 等）須確認其是否需要宣告。
- [ ] **App Privacy 營養標籤**：依實際資料收集填寫；若確實無收集則如實申報，並確保程式與標籤一致。
- [ ] **隱私權政策網址**：必填，內容與實際行為一致。
- [ ] **最低功能（4.2）**：提供完整的錄音／匯入→轉錄→校對→匯出流程，不是網頁包裝；審核備註提供測試步驟與一段可用的測試音訊。
- [ ] **模型下載（2.5.2）**：下載的是模型資料，非可執行程式碼；審核備註說明下載來源、用途與大小。首次啟動即使模型未下載，也要有可評審的內容（例如附一個小型內建模型，或提供示範專案），避免審核員因無法下載而退件。
- [ ] **使用者生成內容與錄音同意**：內建錄音同意提示。
- [ ] **無障礙**：Dynamic Type、VoiceOver、深色模式、對比度通過手動與 Accessibility Inspector 檢查。
- [ ] **裝置與方向**：iPhone／iPad 截圖（依 App Store Connect 當時要求的尺寸）；若支援 iPad，需有平板版面。
- [ ] **簽章與建置**：以 Release 設定在真機上 Archive；啟用 Bitcode 非必要（已移除）；檢查 App 大小與啟動時間；TestFlight 內部測試後再送審。
- [ ] **匯出合規**：App 若只使用系統加密（HTTPS），在 Info.plist 設定 `ITSAppUsesNonExemptEncryption` 並如實回答；若使用其他加密須依規定處理。
- [ ] **年齡分級與類別**：依問卷如實填寫；類別建議「生產力」。

### Google Play

- [ ] **Data safety 表單**：如實申報（資料是否收集／分享／加密）；與程式一致。
- [ ] **權限**：`RECORD_AUDIO`（錄音時才請求）；通知權限（Android 13+，用於處理完成提示）於適當時機請求；避免申請廣泛儲存權限，改用 Storage Access Framework／Photo Picker。
- [ ] **前景服務**：宣告 `FOREGROUND_SERVICE` 與對應類型權限，並在送審表單說明用途。
- [ ] **目標 API 等級**：符合 Play 當時的最低 targetSdk 要求。
- [ ] **64 位元與 16 KB 頁面大小**：原生函式庫（Rust、sherpa-onnx、llama.cpp）須支援 arm64-v8a，並以 16 KB 頁面對齊建置（新版 Android 要求），否則可能無法在新裝置安裝。
- [ ] **App Bundle（AAB）**、Play App Signing、內部測試軌道先行。
- [ ] **Edge-to-edge、深色主題、字級 200%、TalkBack**：手動檢查。
- [ ] **隱私權政策網址**與商店資訊（截圖、簡短說明）。

### 兩平台共同

- [ ] 離線可用性：關閉網路後，已下載模型的完整流程可運作；未下載模型時有清楚入口。
- [ ] 中斷測試：轉錄中強制結束 App、切換 App、來電、低電量、儲存空間不足，皆不遺失已儲存內容且不閃退。
- [ ] 真機長檔測試：至少 60 分鐘音訊完整跑完並記錄溫度、記憶體、耗電。
- [ ] 第三方授權頁完整。
- [ ] 崩潰回報：若使用，須是不上傳內容的方案並於隱私申報揭露；否則僅使用系統提供的崩潰記錄。
