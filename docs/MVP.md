# Transcript Plus：MVP 需求與驗收

日期：2026-09-29｜狀態：可供開發拆工的設計初稿，尚未實作。

## 1. 產品定位

讓使用者將本機影音轉成可校對的逐字稿，再從同一份資料產出可發布字幕、會議摘要與待辦。主要價值是減少「辨識完成到整理完成」的人工時間。

首版優先服務繁體中文的訪談、Podcast、課程與一般會議整理者；兼顧需要 SRT／VTT 的創作者。原始英文保留英文，中英混用可處理；台語、其他語言與多人同時發言的品質不列首版承諾。

依據原始需求第 25 節，保留匯入、轉錄、字詞時間、講者分離、逐字稿編輯、字幕斷句、字幕編輯、SRT／VTT、摘要、待辦十項核心能力。原文件的雲端優先方案改為本機優先，以符合此次單機安裝要求。

### 規劃假設

以下為本次設計採用的預設，並非使用者已確認條件：

- 單一作業系統使用者、無註冊登入、無自建伺服器；資料及推論留在電腦。
- 模型可由使用者主動下載，也可由離線模型包匯入；模型備齊後可全程斷網工作。
- 首波為 Windows 11 x64 與 macOS 14 以上 Apple Silicon；Windows ARM、Intel Mac、較舊系統另行驗證，不由「跨平台」推定全部支援。
- 建議測試基線：Apple M1／16 GB、Intel i5-1345U／16 GB、SSD、無獨立顯卡。這是驗證設備規格，尚非已證實最低需求。
- 首版單檔上限暫定 2 小時、4 GiB，以較先到達者為準；開發前驗證解碼、磁碟及長檔記憶體。正式限制依結果調整。
- 首版每次匯入一個檔案，可依序建立多個工作排隊；不包含資料夾監控與大量批次套版。

## 2. 首版功能與驗收

| ID | 必備能力 | 可驗收行為 |
|---|---|---|
| MVP-01 | 桌面安裝與初次設定 | 安裝後從應用程式圖示啟動，不要求使用者安裝 Python、Node、Rust 或操作終端機；缺模型時顯示容量、狀態及取得方式。 |
| MVP-02 | 本機影音匯入 | 支援 WAV、MP3、M4A、MP4、MOV 中經驗證的編碼；檢查實際可解碼音軌，拒絕損壞、無音軌或超限檔案，顯示中文原因。副檔名不等於所有 codec 均支援。 |
| MVP-03 | 離線轉錄 | 產出整份逐字稿、片段時間與可用字詞時間；沒有語音時顯示「未偵測到語音」，不捏造內容；缺漏字詞時間須標記。 |
| MVP-04 | 工作管理 | 顯示排隊、階段、已耗時、失敗原因；可取消及重試，重啟後保留工作和已完成階段；未知進度不顯示猜測百分比。 |
| MVP-05 | 播放與校對 | 點片段跳播；字詞時間可靠時可點詞跳播；支援播放／暫停、倍速、搜尋、修改文字、自動儲存、復原及重做；儲存狀態可見。 |
| MVP-06 | 講者分離與修正 | 自動產生匿名講者，可選填估計人數、改名、改派單段、合併群組；無把握標成待確認，不以群組推斷真實姓名。 |
| MVP-07 | 字幕斷句 | 依標點、停頓、講者與字數產生字幕，最多兩行；可調字數／閱讀速度等設定；有可靠詞界時自動取得拆合後時間。 |
| MVP-08 | 字幕編輯 | 文字介面拆句、合句、換行，附簡單時間微調；改字造成時間失效時明示待核對，可人工修正；預覽與匯出使用同一版字幕。 |
| MVP-09 | 匯出 | UTF-8 SRT、VTT、TXT、結構化 JSON；摘要／待辦可匯出 Markdown。使用已儲存版本，檔名可選，覆寫前提示。 |
| MVP-10 | 本機摘要與待辦 | 產生摘要、決策、待辦，附可跳播原文；未明示負責人或日期則留空；修改來源後標示過期，提供重產生。 |
| MVP-11 | 模型與本機資料管理 | 查看模型／專案容量、缺檔與毀損；可匯入模型包、刪除專案與快取；升級不覆蓋資料。 |

MVP-01～11 均為完整 MVP 的交付範圍。可先交付轉錄／字幕 Alpha，再補講者與摘要 Beta；不能把尚缺後兩者的版本宣稱為本文件完整 MVP。個別使用者可不安裝講者或摘要模型，此時對應功能明示未啟用，核心編輯仍可用。

### 字幕預設與編輯邊界

初始中文設定：每行最多 18 個可見字元、最多兩行、每則建議 1～7 秒、閱讀速度警示值每秒 9 字；英文先採每行 42 字元。以上是待使用者測試調整的產品預設，並非通用字幕標準。中英混排以 Unicode grapheme cluster 計數，空白不計閱讀速度。

自動斷句優先遵守已知講者切換、停頓及標點，再評估字數與閱讀速度。不能為湊足最短顯示時間延伸到下一個發言；無法同時滿足時保留有效時間並顯示警示。人工確認的斷句不得因重產生直接被覆蓋。

「自動重新計時」首版限於已有可靠詞界的拆句／合句。任意改寫、增加原音沒有的字、在單一 ASR 詞組內拆分，不承諾自動精準對齊。保留片段播放、顯示待核對並提供手動時間設定；局部 forced alignment 列為下一版。

## 3. 使用者流程

1. 安裝、啟動，完成磁碟與模型檢查；選擇下載或離線匯入模型。
2. 拖入影音，輸入標題，選擇轉錄語言及是否執行講者分析。
3. 匯入原檔副本後排隊，依序前處理、轉錄與講者分析；可先看已完成轉錄。
4. 在工作台播放與修正文字、講者；系統顯示已儲存／儲存中／失敗。
5. 切到字幕頁，選預設、拆合文字、檢查待核對時間，播放預覽。
6. 需要會議紀錄時，對已儲存版本執行摘要，檢查引用與待辦。
7. 匯出字幕、逐字稿或會議紀錄；重開軟體可繼續同一專案。

首頁提供專案列表、搜尋標題、工作狀態與「匯入」；工作台為播放器加「逐字稿／字幕／摘要與待辦」三個頁籤。右側顯示當前頁籤的講者或字幕設定。模型管理與儲存空間放設定頁，不要求一般使用者理解推論參數。

關閉視窗時，如有工作，提供「繼續背景處理」或「停止並退出」；背景模式可從系統列回到主視窗。完整退出會停止整個子程序樹。被強制結束後，重開標為中斷，由使用者明確重試。

## 4. 首版不做

| 後續階段 | 功能 |
|---|---|
| v0.2 | 局部強制對齊、ASR 分塊續跑、專有名詞詞庫、翻譯與雙語字幕、批次匯入、完整專案搬移包 |
| v0.3 | ASS、燒錄影片、品牌樣式、動態字幕、精華片段、跨專案搜尋與 Ask AI |
| 未定 | 即時麥克風／系統音訊錄製、Zoom／Meet Bot、雲端同步、多人協作、API／Webhook、聲紋名冊與跨檔認人 |

首版的影片播放代理檔僅用於相容播放，不提供成片剪輯或字幕燒錄。片內文字搜尋屬必備；跨專案全文索引另做。初版以手動安裝新版更新，不包含自動更新服務。

## 5. 驗收與產品指標

先建立可合法使用的 12 份測試素材：3 份單人中文、3 份中英混合訪談、3 份 2～4 人會議、3 份含噪音或靜音的邊界案例；其中涵蓋 10 分鐘、60 分鐘及 120 分鐘長度。調參與驗收片段分開。FABO 的企業錄音不直接當新產品測試資料。

| 項目 | 初始驗收目標／測量方式 |
|---|---|
| 安裝與離線 | 兩平台無開發環境的乾淨機可完成安裝→模型匯入→斷網轉錄→編輯→摘要→匯出；不依賴開發者模型快取。 |
| 資料正確 | 保存後重開文字、講者、字幕相同；匯出版本一致；所有字幕時間滿足 `0 ≤ start < end ≤ duration`，單一字幕軌不重疊。 |
| 完整性 | 120 分鐘檔案可處理到尾段；尾端有語音時有結果，無語音則明確紀錄，不用字幕必須貼齊媒體結尾判斷。 |
| 編輯連動 | 測標點變更、插字、刪字、跨句合併及講者修正；失效時間不得假裝有效，過期摘要不得當新結果。 |
| 中斷 | 前處理／ASR／講者／摘要各階段測取消、正常退出、強制結束與重新啟動；已儲存編輯與已完成階段保留，無孤兒推論程序。 |
| 語音品質 | 乾淨中文 CER 暫定 ≤15%；英文另報 WER；中英混合及噪音分開報告。由人工標註資料量測，第一個技術驗證里程碑確認門檻合理性。 |
| 講者品質 | 報告 DER 的 collar、重疊計分方式及人工修正時間；另以無重疊測試段的講者正確時間占比 ≥85% 作初始目標。 |
| 時間準確 | 人工抽查至少 100 個可靠詞界，絕對誤差 p90 暫定 ≤300 ms；詞／字分界定義須一致；另報缺少可用詞界比例，避免只挑容易樣本。 |
| 摘要可信度 | 每項引用可找到原文；驗收樣本不應出現原文未支持的負責人、期限或承諾。引用有效不代表語意必然正確，另做人審。 |
| 效能 | 以各目標機記錄 ASR 的 RTF＝處理秒數／音訊秒數；候選 small 模型初始目標 ≤1.5。全程序峰值 RAM 暫定 ≤10 GiB，摘要另報耗時；均未實測。 |
| 編輯流暢度 | 2 小時逐字稿用虛擬清單呈現，點擊／輸入互動 p95 目標 <100 ms；儲存防抖 800 ms，提交後 2 秒內完成或顯示錯誤。 |
| 工作流價值 | 5 位試用者、相同 10 分鐘素材，以交叉順序比較原工具，字幕人工整理時間中位數減少 ≥30%；不預先宣稱達標。 |

以上數值是擬定門檻，不是現行成績。G0 可依測試修訂，但須保留調整理由；未達標時降低模型或支援範圍須更新需求，不默默放行。統計預設只留本機，研究資料由使用者主動匯出。

## 6. 里程碑與交付

以 2 位熟悉桌面／前端與 Python AI 的工程師、兼職設計與測試估算 8～12 週；不是排程承諾，模型授權、硬體及簽章準備可能增加時間。

| 門檻 | 估計 | 完成條件 |
|---|---|---|
| G0：雙平台技術驗證 | 第 1～2 週 | 兩平台打包最小桌面程式與 Python 核心；測影音播放、詞時間、講者、本機摘要、記憶體及模型條件。鎖定模型與依賴；無法打包時在此改選方案。 |
| G1：轉錄 Alpha | 第 3～4 週 | 匯入、儲存、排隊、播放、轉錄校對、取消／重試，兩平台安裝測試。 |
| G2：字幕 Alpha | 第 5～6 週 | 共用 Transcript 契約、字幕拆合與時間有效性、SRT／VTT／JSON、版本與復原。 |
| G3：完整 Beta | 第 7～8 週 | 講者校對、摘要／待辦與引用、過期處理、模型管理、長檔驗收。 |
| G4：可交付 MVP | 第 9～12 週 | 簽章／公證、離線包、升級／移除、乾淨機測試與 5 位使用者工作流評估完成。 |

正式交付包含兩平台安裝檔、相容模型包與 manifest、操作說明、第三方清單、驗收報告及已知限制。G0～G3 產物是內部測試版，不等同公開發布。

## 7. 待產品確認事項

優先確認：字幕創作者與會議整理哪一類為主要客群、是否必須支援 Intel Mac／Windows ARM、是否禁止任何模型下載、預期典型檔案長度與可接受處理時間。暫按第 1 節假設推進設計；若將雲端模型列為必要能力，需要另訂資料外送與成本規格。
